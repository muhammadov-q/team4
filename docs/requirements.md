# Requirements

What the course asks of the project, from the project brief of Advanced Software Engineering (MSc, University of Fribourg, as of 2026-09). Our own requirements are user stories, written as GitHub issues ([[workflow/issues]]).

## Goal

Design and build a web-based application for recognizing, analyzing and understanding historical manuscripts. The team chooses the features.

## Hard constraints

- Scrum, driven by user stories. Each story has acceptance tests (functional requirements) and a Definition of Done (non-functional requirements).
- One team member is the Product Owner and drives the development of the application.
- Continuous integration with automated tests that run at least when a feature branch is merged.
- Documentation of the technology stack, the system architecture, selected classes (class diagrams), selected interactions (sequence diagrams), the AI models and the database.

The brief recommends GitHub Projects and Issues for Scrum, GitHub Actions for CI, and running the app locally on a laptop.

## Grading

The team work is 50% of the final grade, in three equal parts:

- Pattern recognition quality: challenging tasks solved with state-of-the-art models, used correctly, with well-designed user interaction.
- Software quality: requirements (user stories), CI, design principles and patterns, testing and documentation.
- Team effort and presentations.

To be admitted to the written exam, each member needs a reasonable contribution to the team work, at least 8 of the 10 weekly meetings ([[meetings/README]]) and at least 1 of the 2 presentations.
